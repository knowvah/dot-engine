# T14 observations (full fresh sweep against the carried oracle)

## Observation: survey parallelism capped by heavy slots
- **Context**: `SURVEY_CONCURRENCY=5 npm run survey`, 212 min
- **Finding**: `survey.ts` holds extra workers behind `HEAVY_SLOTS=2`; while
  world.gv and 2475_1 run, only ~2 workers are active for most of the run.
- **Impact**: raising SURVEY_CONCURRENCY barely shortens a full survey.
- **Confidence**: Medium

## Observation: map-walk has no nondeterminism probe
- **Context**: map-walk fdp, graphs-b100
- **Finding**: cmapx and imap come from separate native draws, so on fdp the
  pair can disagree (imap diverged, cmapx conformant); re-run → conformant.
- **Impact**: map-fdp divergences may be oracle variance, not port defects.
- **Confidence**: High

## Observation: fixed 180 s port floor times out big dot graphs under load
- **Context**: dot-walk / xdot-walk on 2646, 2371, 2343, 2095_1
- **Finding**: budget = max(180 s, 3 × cached oracle ms); the carried
  oracle's faster cached time (2646: 117.7 s vs 148 s) lowers the budget,
  and at load > 15 these ids time out. Re-run at load < 5 → pass.
- **Impact**: run the big dot graphs at low load or concurrency 1.
- **Confidence**: High

## Observation: `npm run survey` regenerates the pristine GVBINDIR
- **Context**: `survey:setup` = gen-headless-gvbindir.sh with pristine defaults
- **Finding**: it rewrites /tmp/ghl1611 although survey.ts reads the carried
  `/tmp/ghl1611-carried`; harmless, but stale since ADR-0003.
- **Impact**: a wiped carried GVBINDIR is not restored by `npm run survey`;
  use build-carried-oracle.sh.
- **Confidence**: High
