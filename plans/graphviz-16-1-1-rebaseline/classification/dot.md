## Method

- Each of the 41 survey ids was rendered `-Tsvg` with both natives (`render.sh`; 900 s cap). The ids
  `1514`, `1581` and `894589` were also rendered in `dot`, `xdot`, `json`, `cmapx`, `imap`, `plain`
  and `plain-ext`. dot is deterministic: 4 runs of 16.1.0 `-Tdot`/`-Tjson` on `1581` gave one hash
  each.
- **Counterfactual for #158.** `pc/src/layout/dot/mincross-flat.ts` is a throwaway copy of the
  unchanged port. It adds 16.1.1's `valid_rank` behind `CF158=1`: `flatReorderBuildTemprank` returns
  false on a node that is neither (in=0 and out=0) nor (unmarked and in=0), and `flatReorderRank` then
  skips the reorder and the "make LR" loop. I ran it on the 35 conformant→X ids. With `CF158` unset
  the copy is conformant to native 16.1.0 on all 35. That proves the port matches 16.1.0 and the
  harness compares the same way (`cmp.ts` calls the survey's `compareSvg(..., 'deterministic')`).
  With `CF158=1` the copy is **conformant to native 16.1.1 on 33 of 35** (`258` run first, then 32
  of the other 34). It leaves `1314` (S3) and `700813` (residual, S1 note).
- Native exit status for the oracle-error transitions comes from the `.rc` files. Crash frames come
  from the macOS crash reports `~/Library/Logs/DiagnosticReports/dot-2026-11-12-175652.*.ips`,
  written by this task's 16.1.0 runs (plugin `8.0.15`). lldb and `sample` could not attach inside
  the sandbox: both hung, and I killed them.

## S1: #158 flat_reorder (34 ids, conformant → diverged/structural-match)

- **C change:** `9fb21f570` `lib/dotgen/mincross.c:flat_reorder` (upstream 2368, 2854).
- **Mechanism:** 16.1.1 marks a rank invalid as soon as one node has a constraining incoming flat
  edge, or is already marked with a constraining flat edge. An invalid rank skips both the
  topological reorder and the "nonconstraint flat edges must be made LR" loop. `is_a_cluster` is
  true for the root, so in practice every rank holding a `rank=same` flat edge with weight > 0 keeps
  its mincross order. The edge then runs right-to-left instead of being re-sorted left-to-right.
- **Ruled out:** the `mincross.c` diff over 16.1.0..16.1.1 has no other behavioural hunk (the rest
  is `UNUSED` and a brace reshuffle). The counterfactual turns 33 of the 34 ids conformant to 16.1.1
  with this one change.
- **ids (34):** `121`, `1444`, `1444-2`, `1453`, `2239`, `2368`, `2368_1`, `2521`, `258`, `2592`,
  `700813`, `graphs-b58`, `graphs-html2`, `graphs-in`, `graphs-longflat`, `graphs-ports`,
  `graphs-shells`, `linux.x86-html2_dot`, `linux.x86-ordering_dot`, `linux.x86-ordering_dot1`,
  `linux.x86-ports_dot`, `macosx-ordering_dot`, `macosx-ordering_dot1`, `nshare-html2_dot`,
  `nshare-ordering_dot`, `nshare-ordering_dot1`, `nshare-ports_dot`, `share-longflat`, `share-shells`,
  `tree-graphs-directed-longflat`, `tree-graphs-directed-sdh`, `tree-graphs-directed-shells`,
  `windows-longflat`, `windows-shells`. (structural-match: `1444`, `1444-2`, `2592`, `graphs-html2`,
  `graphs-in`, `graphs-longflat`, `linux.x86-html2_dot`, `nshare-html2_dot`, `share-longflat`,
  `tree-graphs-directed-longflat`, `windows-longflat`; the other 23 diverged.)
- Side effects on stderr: 16.1.0's `Error: in routesplines, illegal values of prev 1 and next 1,
  line 378` on `2368` (×2) and `2368_1` (×1) are gone in 16.1.1. `1453` and `2368_1` diverge on
  childCount only, because 16.1.1 now draws an edge that 16.1.0 lost (e.g. `1453` gains
  `CMD_POST_DECODE_LITERALS->CMD_BEGIN`).
- **700813 residual:** under `CF158=1` this id still differs, at structural-match maxΔ 12. The two
  flat 2-cycle edges `B->C` and `C->B` swap routes: native 16.1.1 gives `B->C` the inner loop
  (x ≥ 8.58) and the copy gives it the outer one (x ≥ −1.48). The point sets are mirror-identical.
  The full `dotsplines.c` diff for 16.1.0..16.1.1 touches no `edgecmp`, `make_flat_edge` or
  `setflags` code. The residual is therefore the port's group order for a back flat edge that is
  left unreversed, a state 16.1.0 never produced. It is not a second C change (confidence: Medium,
  because C's group order was not traced). The #158 port should check it.
- Example (`258`, cluster `{rank=same; A -> B}`; A and B swap, and the edge runs right-to-left):
  ```
  < <ellipse fill="none" stroke="black" cx="43" cy="-34" rx="27" ry="18"/>      (A)
  > <ellipse fill="none" stroke="black" cx="115" cy="-34" rx="27" ry="18"/>     (A)
  < <path fill="none" stroke="black" d="M70.28,-34C72.28,-34 74.28,-34 76.29,-34"/>
  > <path fill="none" stroke="black" d="M87.75,-34C85.75,-34 83.75,-34 81.74,-34"/>
  ```

## S2: #158 forum cluster hang (2 ids, oracle-error → conformant)

- **C change:** `9fb21f570` `lib/dotgen/mincross.c:flat_reorder` ("fixes #2368, fixes #2854"). Its
  forum link (`.../clustered-subgraph-leads-to-crash-in-dot/3395`) is the source of both inputs.
  `2855.dot` is `2854_1.dot` plus a 3-line comment header.
- **Exit status:** 16.1.0 `124 900s` (killed at the cap) on both; 16.1.1 `0 0s` on both.
- **Mechanism:** `class2(group0)` calls `mark_clusters(group0)`, which nulls `ND_clust` of group0's
  own nodes (`cluster.c:310`). `ordered_edges(group0)` then builds weight-1 FLATORDER flat edges for
  the inherited `ordering="in"`. Those edges are constraining inside the `cluster=true` subgraph.
  16.1.0's `flat_reorder` reorders that rank anyway, and the following `mincross(group0, 2)` never
  returns. 16.1.1 skips the rank.
- **Evidence:** `dot -v` on 16.1.0 stops after `mincross: pass 2 iter 0 trying 0 cur_cross 3
  best_cross 3`. That is the first iteration of `mincross_clust(group0)`, right after
  `flat_reorder(group0)` (`mincross.c:546`). 16.1.1 continues to `iter 1..6`. The same input reaches
  `dot_mincross` with the same `Maxrank = 4` in both versions, and `mincross.c` has no other
  behavioural change. ADR-0002 files `2855` under #149 because of upstream issue 2855 (`nop` edge
  order, test `test_2855`). For `-Tsvg` the input is the 2854 graph, and the hang it fixes is #158's.
- Example: `old/2854_1.svg.rc` = `124 900s`; `new/2854_1.svg.rc` = `0 0s` (same for `2855`).
- Port note (not a 16.1.1 change): the port never sees these flat edges. A `CF_TRACE2` trace shows
  `flatReorder` on `G` and on `group0` with `has_flat_edges` undefined, and `CF158` never fires. The
  port is conformant because a skipped rank and a rank without flat edges give the same order here.

## S3: #162 aux edge too long (1 id, conformant → diverged)

- **C change:** `f86899fcc` `lib/dotgen/position.c:make_aux_edge`, plus its plumbing (`73c1fd4d1`
  `make_edge_pairs`, `f1e5ad67d`/`d3f55476c` `create_aux_edges`, `f444e5192` `dot_position`).
- **Mechanism:** both versions print `Error: Edge length 272931242864.483337 larger than maximum
  2147483647 allowed.` and exit 1. 16.1.0 clamps the aux edge and positions the graph at
  ~1.68e12 pt. 16.1.1's `make_aux_edge` returns NULL, so `dot_position` fails and the render emits an
  unpositioned graph: an 8×8 pt page, node `s` at x=0, node `n0` absent.
- Example (`1314`):
  ```
  < <svg width="200819557pt" height="-425618343pt"
  > <svg width="8pt" height="8pt"
  < <ellipse fill="none" stroke="black" cx="272931242819.48" cy="-841600780840.48" .../>
  > <ellipse fill="none" stroke="black" cx="0" cy="-841600780840.48" .../>
  < <title>n0</title>                        (node2 group missing in 16.1.1)
  ```

## S4: #159 flat_edges abomination for ND_other (1 id, oracle-error → errored)

- **C change:** `4e50c9abd` `lib/dotgen/flat.c:flat_edges` (upstream 2756): the prep loop also scans
  `ND_other(n)` for `ED_label && !ED_adjacent` before calling `abomination`.
- **Exit status:** 16.1.0 `139` (SIGSEGV); 16.1.1 `1` with a complete SVG.
- **Mechanism:** without rank −1, `flat_node` reads `GD_rank(g)[r-1].v[0]` for a labelled flat edge
  found only in `ND_other` and dereferences NULL. The crash report shows
  `EXC_BAD_ACCESS KERN_INVALID_ADDRESS at 0x0`: `flat_node+380 ← flat_edges+1152 ← dot_position+164`
  (plugin 8.0.15). The port still mirrors 16.1.0 and now surfaces as `errored`, `Cannot read
  properties of undefined (reading 'v')`.
- Example (`2723`): `.rc` `139 0s` → `1 0s`; new stderr: `Error: in routesplines, illegal values of
  prev 1 and next 1, line 375` / `Error: lost 415 407 edge`.

## S5: #151 checkpath all-degenerate boxes (1 id, oracle-error → errored)

- **C change:** `94719107c` `lib/common/routespl.c:checkpath` ("fixes #2773, #2774, #2776, #2778").
- **Exit status:** 16.1.0 `138` (SIGBUS); 16.1.1 `1` with a complete SVG.
- **Mechanism:** when every box is below threshold (`boxn == 0`), 16.1.0 goes on with `boxes[0]` and
  `Pshortestpath` faults. The crash report shows `KERN_PROTECTION_FAILURE`:
  `Pshortestpath+792 ← routesplines_+3104 ← dot_splines_+11704`. 16.1.1 returns 1, the edge is
  lost, and layout continues. The port mirrors 16.1.0 and now surfaces as `errored`, `Cannot read
  properties of undefined (reading 'll')`.
- Example (`2778`, new stderr):
  ```
  > Error: in checkpath, all bounding boxes are below threshold
  > 0 boxes:
  > Error: in routesplines, Pshortestpath failed
  > Error: lost d0 Se3ffa81011d69e3db000538bf02fa1d0 edge
  ```

## S6: stale 16.1.0 registry, native unchanged (2 ids, → conformant)

The orchestrator's premise covers 39 of the 41 survey rows. These 2 come from port commits on `main`.
The 16.1.0 `parity.json` was last written at `b2c10dea` (2026-10-27). About 50 `src/` commits landed
on `main` after that and before the T3 re-survey, two of which settle these ids.

- `1581` (diverged, childCount → conformant). The native 16.1.0 and 16.1.1 SVGs are byte-identical
  apart from the banner, both in fresh renders and in the cached
  `~/.cache/dot-engine/oracle/oracle/{c2e610dcc867,001cc35440c0}/1581.svg`. Today's port gives one
  hash over 3 runs, and its SVG has the same 20 groups as native. The fix is port commit `ad667824`
  (2026-11-09, "test each edge's spline box against the page clip"), whose body says "1581 under dot
  -Tsvg gains two empty edge groups … byte-equal to native". The only native delta is stderr:
  ```
  < Error: install_in_rank, line 1158: G %0 rank 9 i = 0 an = 0
  > Error: install_in_rank, line 1157: G %0 rank 9 i = 0 an = 0
  ```
- `2475_1` (errored "Last few GCs" → conformant). The cached native SVGs (101,313,598 bytes each)
  are identical apart from the banner (0 diff lines). The change is a harness heap cap:
  `4d8c4e0a` (2026-11-10) added `PORT_HEAP_MB = { '2475_1': 13 * 1024 }` (`test/corpus/survey.ts:135`)
  and halved the port's aux-edge memory. Before it, the port died at V8's default heap.

## F2: #149 write_body never re-declares an edge in a sibling subgraph (4 rows)

- **C change:** `61e599d14` `lib/cgraph/write.c:write_edge`/`write_body` (the `EDGE_DONE` sentinel),
  on top of `230a65310` (edges written in creation order after a body's nodes) and `072a4d3ef`.
- **Mechanism:** 16.1.1 marks each written edge done and never writes it again in a later sibling
  subgraph. 16.1.0 re-declared it, and the port still does: walk diffs `[extra]
  subgraph:<anon>/edge:Act_21->Act_22#0: port=declared native=<absent>` (`1514`) and
  `…Act_23->Act_24#0…` (`1581`). xdot shows the same as `edge:…#2[missing-object]`.
- **Evidence:** the port's `-Tdot` (`render-one-dot.ts`) is byte-identical to native 16.1.0 on both
  ids (0 diff lines) and differs from 16.1.1 by 5 (`1514`) and 25 (`1581`) lines. The other formats
  (json, cmapx, imap, plain, plain-ext) are byte-identical natively for both ids.
- **Rows:** `1514` dot pass→diverged, xdot conformant→diverged. `1581` dot `<absent>`→diverged,
  xdot `<absent>`→diverged.
- Example (`1514` `-Tdot`):
  ```
  < 		Act_1 -> Act_3	[pos="e,34.637,108.1 34.637,143.7 ..."];      (moved after nodes)
  > 		Act_1 -> Act_3	[pos="e,34.637,108.1 34.637,143.7 ..."];
  < 		Act_21 -> Act_22;                                            (sibling re-declaration dropped)
  ```
