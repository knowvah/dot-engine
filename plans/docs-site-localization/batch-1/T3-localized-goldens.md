# T3 — Per-locale showcase pages and golden descriptions

## Context

`copy-goldens.mjs` generates `showcase/{index,<engine>}.md` and
`.vitepress/goldens.json` (descriptions from `test/golden/manifest.json`).
Every locale needs its own showcase pages (else `/xx/showcase/` 404s) with
translated titles, blurbs and golden descriptions
([decisions.md#goldens](../decisions.md#goldens),
[#showcase](../decisions.md#showcase)).

## Task

1. Move `ENGINE_BLURB` and the showcase page prose into a per-locale shape:
   English stays in `copy-goldens.mjs`; locale text comes from an optional
   `showcase` block — **add it to `DocsLocale` only via T1's interface if T1
   left room; otherwise read it from `locales/goldens/<p>.json` under a
   reserved `"$showcase"` key** (no write to `i18n.ts` — not in this
   write-set). Document the choice in the journal.
2. Discover locales by listing `.vitepress/locales/*.ts` (native import,
   same as `i18n.ts`). For each, write `<p>/showcase/{index,<engine>}.md`
   (links prefixed; the `/conformance` link → `/<p>/conformance`) and
   `.vitepress/goldens.<p>.json` with descriptions from
   `locales/goldens/<p>.json`, falling back per-id to English.
3. `GoldenGallery.vue`: load `goldens.<p>.json` for the active locale
   (root → `goldens.json`); resolve its strings via `stringsForLang`.
4. `.gitignore`: `docs-site/*/showcase/`, `docs-site/.vitepress/goldens.*.json`,
   and `docs-site/.vitepress/i18n-hashes.json` (generated by T4).

## Write-set

`docs-site/copy-goldens.mjs`, `docs-site/.vitepress/theme/GoldenGallery.vue`,
`.gitignore`, `test/docs/goldens-i18n.test.ts` (+ fixtures under
`test/docs/fixtures/goldens/**`).

## Read-set

`copy-goldens.mjs` (all, 100 lines), `GoldenGallery.vue` (all),
`i18n.ts`, `theme/strings.ts` (T1), `test/golden/manifest.json` (shape only).

## Interface contracts (outputs)

`locales/goldens/<p>.json`: `{ "$showcase"?: { title, intro, blurbs:
Record<engine,string>, … }, "<goldenId>": string, … }` — consumed by
translation part c and by T4's status script. Export a pure
`localizeGoldens(manifestEntries, translations)` →
`{ entries, missingIds: string[] }` for T4 and T29.

## Acceptance criteria

- Given a fixture locale `xx` with a goldens file covering 2 of 3 ids, when
  `localizeGoldens` runs, then the 2 descriptions are translated, the third
  is English, and `missingIds` names it.
- Given registered `xx`, when `copy-goldens` runs, then
  `docs-site/xx/showcase/dot.md` exists and links `/xx/conformance`.
- Given no locales, then output is byte-identical to today's.
- Gallery strings resolve per locale (same pattern as T2).
