# T1 — scale `engine-walk.ts`'s render budget

**Agent:** `typescript-pro` · **Depends on:** — · **Commit:** one

## Context

`dot-engine` is a faithful TypeScript port of Graphviz C; `test/corpus/` holds
the differential-parity harness that compares the port against the native C
binary (the oracle). Five walkers sweep the corpus, one per output surface:
`survey.ts` (SVG), `engine-walk.ts` (xdot), `json-walk.ts`, `map-walk.ts`,
`plain-walk.ts`.

`engine-walk.ts` is the only one whose port-render timeout is a **hard-coded
90_000 ms** with no scaling and no env override (~line 150; the oracle side is a
hard-coded 300_000 ms at ~line 114). That already manufactures phantom `timeout`
rows: `2108` is `timeout` on all three iterative xdot tracks, and `1652` is
`timeout` on fdp while rendering fine on neato/sfdp.

This blocks the whole mission: a `timeout` row is invisible to the attribution
harness, which selects only `status === 'diverged'`
(`attribute-divergence.ts:441-450`). Without this fix, `2621` can never be
attributed and 4 of the 7 target rows stay stuck.

`survey.ts` solved the same problem in `b7d106e5`. **Mirror it — do not invent a
different model.**

## Task

Extract the budget computation into an exported pure function and give it the
same three-term shape `survey.ts` uses, plus env overrides. The file has no test
today, so the extraction is what makes it testable — write the tests first.

Required behaviour:
- budget = `max(FLOOR, MULT x nativeMs, MULT x recorded portMs)`
- cost data comes from `test/corpus/perf.json` (`results[].portMs`) and
  `test/corpus/native-timings.json` (`timings`), read defensively — an
  unreadable/absent file contributes nothing and must not throw
- env overrides: multiplier, floor, and the oracle cap
- the old bare `90_000` must not survive anywhere as an effective default

Read `test/corpus/survey.ts:115-175` for the reference implementation and its
reasoning (`renderBudgetMs`, `expectedCostMs`, `CACHED_ORACLE_MS`). Note
`survey.ts` also falls back to the oracle ms recorded beside each cached SVG,
because `2621` appears in neither cost file; decide whether `engine-walk` needs
that third signal (it has its own per-engine oracle cache) or whether the
now-recorded `2621` timings suffice.

## Interface contract (consumed by T2)

```ts
export function renderBudgetMs(id: string, nativeMs: number): number;
```
Env overrides (names are yours to choose, P1 — these are the expected shape):
`ENGINE_TIMEOUT_MULT`, `ENGINE_TIMEOUT_FLOOR_MS`, `ENGINE_ORACLE_TIMEOUT_MS`.
Document the chosen names in the commit body; T2 sets them.

## Acceptance criteria

1. **Given** an id with a recorded `portMs` in `perf.json`, **when**
   `renderBudgetMs` is called, **then** the result is >= `MULT x portMs`.
2. **Given** an id absent from both cost files, **when** `renderBudgetMs` is
   called, **then** the result equals the FLOOR — and is never 90_000.
3. **Given** the floor env override is set, **when** `renderBudgetMs` is called,
   **then** the override wins over the derived floor.
4. **Given** `perf.json` is missing or malformed, **when** the module loads and
   `renderBudgetMs` is called, **then** it returns the floor rather than throwing.
5. **Given** `2621` (portMs 1237043) and the default MULT of 3, **when**
   `renderBudgetMs('2621', 256000)` is called, **then** the result is
   >= 3711129 — i.e. it would not be cut off.
