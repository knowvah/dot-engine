### AD-1: one helper, `svgGraphId`, carries the sequence

- **Decision:** `svgGraphId` returns `job.objId(g.attrs.get('id'), 'graph' + g.seq, true)`.
  Delete `graphObjId` (`src/render/svg-graph.ts:235-245`, doc comment included; move
  its explanation of `root == obj` into `svgGraphId`'s doc) and call `svgGraphId` at
  `svg-graph.ts:284` and `:424`.
- **Rejected:** (a) keep `graphObjId` and point `device.ts` at it: two names for one C
  function (`getObjId` on an AGRAPH) is the duplication item 142 reports; (b) pass the
  sequence in from `device.ts`: every caller would rebuild C's rule.
- **Evidence:** the issue body prescribes it; `emit.c:233-238` (`idnum = AGSEQ(obj)`,
  `pfx = "graph"` when `root == obj`). In the port the graph being rendered is always
  `job->gvc->g`, so `isRoot = true` stays: no `<gid>_` prefix, matching native's
  `a_graph1` (no prefix even though `s` is not the cgraph root).

### AD-3: the HTML-label anchor case uses a ref captured before native's abort

- **Decision:** `subg-html.gv` (subgraph `s` with an HTML graph label whose cell has
  `href`) is rendered by native fine, but native then aborts (SIGABRT/SIGTRAP) in
  `gvFreeLayout` of `s`, after both renders are flushed (`show()` calls `fflush`).
  `regen.sh` ignores that exit status and checks for two complete renders. The test
  asserts the port's `a_graph1_0` anchor id (svg) and `graph1_0` area id (cmapx) equal
  the ids in that ref.
- **Rejected:** drop the HTML case: `device.ts:235` (`setHtmlAnchorObj`) is a separate
  call site that only this case exercises. Investigating the native abort: upstream
  behaviour, out of scope; journal and note it.
