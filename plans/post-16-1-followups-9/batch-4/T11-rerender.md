# T11: a second layout on one graph matches native (plantuml-ts issue 37, AD-11)

**Context:** native's `gvLayout` / `gvRender` / `gvFreeLayout` cycle deletes each object's layout record, so the next layout binds
zeroed records. The port's `freeLayout` keeps them, because `getLayout` is documented to work after `render`, and `render` frees at its
end. The filing is at `~/git/knowvah/plantuml-ts/docs/graphviz-issues/37-rerender-not-idempotent.md`. Read it for the `dot` mechanism
(stale `e.info.to_virt`, stale `e.info.spl`), which it traced for `dot` only.

Measured in planning on 35 smoke ids × 8 engines, in `plans/post-16-1-followups-9/harness/T11/` (`matrix-T0.json`):
- on `plain`, native repeats exactly in 255 of 280 cases, and the port fails 212 of those 255. All engines fail except patchwork (1 case);
- 8 `dot` second renders throw (`reading 'par'`, or `reading 'info'` on null) instead of returning output. Do not assume a single cause;
- on `xdot`, native's second render differs from its first in 35 of 35 cases on every engine. The write-back of layout attributes is the
  suspected cause, untraced. **The bar is native's second render, not idempotence.** The port's second `xdot` render has not been
  compared with native's second render;
- on `plain`, 25 native cases do not repeat (sfdp 14, fdp 5, dot 3, neato, twopi and osage 1 each). Establish whether each is
  nondeterminism or a write-back before comparing.

**Task:**
1. Diagnose first (diagnosis mode). Extend `harness/T11/twice.c` to print both renders, and establish per engine which stale state moves
   the second layout. State the mechanism for the `dot` throws and for native's `xdot` difference.
2. Enumerate every field reached through `e.info`, `n.info` and `g.info` that is set **before** the engine runs and must survive: for
   example `g.root.info.gvc` (part-8 notes), anything `createGraph`'s builder or the parser stamps, and subgraph records. Report the list.
3. Tests first, in a new `src/gvc/rerender.test.ts`, with native's second-render output as fixtures under `src/gvc/__fixtures__/rerender/`
   (generated by a committed `regen.sh`), on `plain` and `xdot`. Cover `dot` with clusters (the throw), neato, fdp, sfdp, circo, twopi, osage
   and patchwork, then these sequences:
   - render, render, render, on `createGraph`'s builder and on `parse`;
   - render, `getLayout`, which must still read the first layout;
   - render with one engine, then with another;
   - `ctx.layout` twice with no `freeLayout`, which must keep native's stale behaviour (the filing's `nofree` output);
   - `renderAsync` and `getDrawOps` twice.
4. Implement AD-11: `freeLayout` runs today's cleanup and marks the graph freed; the next `ctx.layout` resets the records once before the

5. Run the libm gate on the new test.
