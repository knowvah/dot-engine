## T1-discovered addendum to D2: third protected pattern

D2 lists two protected patterns. While authoring the dry run I found a third,
real, load-bearing case not enumerated in `decisions.md`: Claude Code
flattens `/` to `-` in its per-project directory names, so the same
`~/git/graphviz-ts` directory (kept per D7) also appears as the literal
substring `git-graphviz-ts` in prose paths, e.g.:

- `plans/arrowhead-geometry/batch-3/T8-survey-finalize.md:27` —
  `` ~/.claude/projects/-Users-scottseely-git-graphviz-ts/memory/ ``
- `plans/errored-cluster/batch-3/T5-survey-finalize.md:32` — same pattern
- `test/corpus/zz-rebucket-tmp.ts:60` —
  `` /private/tmp/claude-501/-Users-scottseely-git-graphviz-ts/<session>/scratchpad/... ``

Without protection, rule-b (`graphviz-ts/` -> `@knowvah/dot-engine/`) fires
on `git-graphviz-ts/memory/` because it contains the literal substring
`graphviz-ts/`, corrupting a real on-disk reference into
`git-@knowvah/dot-engine/memory/` (nonsense, and not a directory that
exists). `scrub.mjs` now sentinel-protects `git-graphviz-ts` as a third
pattern alongside the two from D2 (see the `PROTECTED_GIT_DASH` constant and
its inline comment). This is a **non-trivial judgment call** — logged in the
final report for the orchestrator to ratify as a formal D2 addendum.

Evidence this was the right call: after adding this protection, the
Total-to-replace figure landed on **exactly 407** — the same number the
planning survey referenced in the T1 task spec — even though the survey's
own text only mentions the two D2 patterns by name. That exact match is
strong (not proof) evidence the survey author already excluded these 3
dash-form paths by hand, just without writing them up as a formal decision.
