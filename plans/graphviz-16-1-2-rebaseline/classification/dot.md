## G1 — 16.1.2 render skip, error in the input (#299)

- **C change:** `19b33b581` "dot: fix: skip rendering when layout has failed" (upstream 2761),
  `cmd/dot/dot.c:main`.
- **Mechanism:** after `gvLayoutJobs`, `main` now calls `agreseterrors()`, which returns `agmaxerr`, the
  highest `agerr` level since the last reset (`lib/cgraph/agerror.c:agerr_va`, `:185 agreseterrors`; warnings
  are level 0, errors 1); any error-level message during layout makes it non-zero and `gvRenderJobs` is skipped,
  so stdout is empty where 16.1.1 rendered the half-laid-out graph.
- **Evidence:** each id run natively from its own directory and from the worktree root, `-Tsvg`: 16.1.1 exits 1
  with a document, 16.1.2 exits 1 with 0 bytes, in both cwds (`$BASE/t12a/n34.summary`). The stderr of the two
  versions is identical except the build path and line numbers the clang-format moved.
- **Ids by the first error that sets `agmaxerr`** (C site in 16.1.2):

## G2 — 16.1.2 render skip, error caused by the harness cwd (#299)

- **C change:** `19b33b581` `cmd/dot/dot.c:main`; the error comes from `common/htmltable.c:size_html_img`
  (`agerrorf("No or improper image file=\"%s\"\n", …)`, `:1053`), called while layout sizes HTML labels.
- **Mechanism:** the input names its image relative to its own directory; the survey runs native with no `cwd`
  option, so from the worktree root the image is missing, `size_html_img` raises an error, and 16.1.2 skips the
  render (16.1.1 exited 1 but rendered without the image).
- **Ids:** `1879`, `2619`, `2821_0`, `2821_1`, `2821_2`.
- **Evidence:** from their own directory both versions exit 0, no error, byte-identical svg apart from the version
  comment. From the worktree root: 16.1.1 exit 1, a smaller document (`1879` 653518 vs 720509 bytes); 16.1.2
  exit 1, 0 bytes. The port at HEAD is conformant with 16.1.1's root-cwd render and **diverges** from the own-dir
  render on all five (`childCount` at the image group): the port draws no image, so its old verdicts matched the
  image-missing output, and running native from the input's directory would turn these five into diverged,
  not conformant.
- **Harness call that sets the cwd:** none sets it. `test/corpus/survey.ts:320` `spawn(cmd, args, { env,
  detached: true })` (called from `oracleSvg`, `survey.ts:395`, with the absolute input path) inherits the
  survey process's cwd: the repo root under `npm run survey` (`package.json:71`). The format walks do the same:
  `dot-walk.ts:186`, `json-walk.ts:181`, `map-walk.ts:184`, `plain-walk.ts:176`, `xdot-walk.ts:115`, none with
  `cwd`. They no longer visit these ids (oracle-error in `parity.json`); before, `1879` and `2619` were walked
  against 16.1.1's image-missing render (`2821_*` were never in the old rosters).
- **Example hunk:** as G1 (`cmd/dot/dot.c`); the triggering line, 16.1.2 `lib/common/htmltable.c:1053`:

