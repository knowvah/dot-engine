# Использование в браузере

@knowvah/dot-engine не использует API, доступные только в Node, и безопасно собирается
в бандл для браузера. На этой странице — две вещи, которые нужно знать при работе на
стороне клиента.

## Сборка в бандл

Библиотека — обычные ES-модули. Любой современный сборщик (Vite, esbuild, Rollup,
webpack) может включить её. Выносить во внешние зависимости времени выполнения нечего,
и размещать артефакты WASM не нужно.

```ts
import { renderSvg } from '@knowvah/dot-engine';

const svg = renderSvg('digraph { a -> b }', 'dot');
document.querySelector('#out')!.innerHTML = svg;
```

[Песочница](/ru/playground) этого сайта делает ровно это — она импортирует механизм и
вызывает `renderSvg` в браузере, без обращений к серверу.

## Измерение текста

Graphviz нужны размеры текста, чтобы задавать размеры меток. @knowvah/dot-engine делает
это автоматически:

- **В браузере** (когда существует `document`) текст измеряется с помощью
  нативного 2D-контекста `<canvas>` — с учётом шрифтов хоста, поскольку это тот же
  шрифт, которым браузер рисует SVG.
- **В Node** по умолчанию используется встроенный измеритель **Estimate** —
  детерминированная модель, безопасная без графической среды, которая повторяет
  собственную функцию Graphviz `estimate_textspan_size`. Для корректной компоновки в
  Node не нужно ни устанавливать `canvas`, ни иметь файлы шрифтов; также доступен как
  необязательный вариант измеритель на основе таблицы поиска (LUT) с хинтингом — для более
  точного приближения к шрифтам хоста без нативной зависимости от canvas. О том, как явно
  выбрать измеритель, см. [Измерение текста](/ru/guide/text-measurement).

Файлы шрифтов для компоновки не требуются ни в каком случае.

## Веб-шрифты: почему важна предзагрузка

Размеры меток вычисляются измерением текста шрифтом. Если начертание объявлено через
`@font-face`, но ещё не загрузилось, браузер измеряет **запасным** шрифтом, и когда
настоящий шрифт приходит, компоновка оказывается неверной. Измерение в Chromium с
JetBrains Mono: рамка метки имела ширину **70,68 pt** при измерении до загрузки
начертания (запасной шрифт) и **124,8 pt** после загрузки.

Асинхронные точки входа (`renderSvgAsync`, `renderAsync`, `renderSvgInto`) избегают
этого: они собирают шрифты, которые запросит граф, загружают их через `document.fonts`
и только потом запускают компоновку. `renderSvgAsync` дал те же 124,8 pt, что и
измерение после загрузки.

```ts
import { renderSvgAsync } from '@knowvah/dot-engine';

const { svg, fontIssues } = await renderSvgAsync(
  'digraph { node [fontname="JetBrains Mono"]; a -> b }',
  'dot',
  { fontTimeoutMs: 5000 },
);
```

- **`fontTimeoutMs`** (по умолчанию `3000`) — это один общий крайний срок для всех
  начертаний, а не для каждого по отдельности.
- **`fontIssues`** — список `{ face, reason }`. `reason: 'failed'` означает, что
  начертание завершилось ошибкой (например, 404) или его загрузка была отклонена;
  `reason: 'timeout'` означает, что оно не загрузилось за `fontTimeoutMs`. В обоих
  случаях компоновка продолжается с запасным шрифтом. Каждая проблема также выводится
  через `console.warn`. Проблемы со шрифтами никогда не отклоняют промис.
- **Ограничение:** сообщить можно только о семействах, объявленных через `@font-face`.
  Системный шрифт или неизвестное имя семейства считается «загруженным» (ждать нечего),
  поэтому неверно написанный `fontname` никогда не попадёт в `fontIssues`.
- **Node и Workers** не имеют `document.fonts`, поэтому предзагрузка шрифтов
  пропускается, а `fontIssues` равен `[]`. Хуки изображений по-прежнему работают. Можно
  передать `fontSet` (любой объект с `load(font)`), чтобы предоставить собственный.

## Рендеринг в страницу: `renderSvgInto`

```ts
import { renderSvgInto } from '@knowvah/dot-engine';

// <div id="graph"></div>
const { element, fontIssues } = await renderSvgInto('graph', dot, 'dot');
if (fontIssues.length > 0) {
  console.warn('fallback fonts used for', fontIssues.map((i) => i.face));
}
```

Она заменяет дочерние элементы элемента с указанным id отрисованным `<svg>`
(возвращается как `element`), используя `DOMParser` и `importNode`, но никогда не
`innerHTML`. Отсутствующий id отклоняет промис с `ERR_INVALID_ARG_VALUE`. SVG по
умолчанию очищается; передайте `sanitize`, чтобы использовать собственный очиститель, или
`trusted: true`, чтобы пропустить очистку. О том, что очиститель удаляет и что
оставляет, см. раздел «Security» в README, и не отключайте Content-Security-Policy.

## Внешние изображения: `setImageSizer`

Когда HTML-подобная метка содержит внешнее изображение (`<IMG SRC="logo.png"/>`),
Graphviz нужны собственные размеры этого изображения, чтобы задать размер ячейки.
(Атрибут узла `image=` не измеряется: узел сохраняет обычную рамку, как в нативном
Graphviz без графической среды.) Поскольку библиотека не может читать файловую
систему, вы предоставляете определитель размера (sizer):

```ts
import { setImageSizer } from '@knowvah/dot-engine';

setImageSizer((src) => {
  // Return the intrinsic { w, h } for this image source, or null if unknown.
  return { w: 64, h: 64 };
});
```

Если ваши графы никогда не ссылаются на внешние изображения, вызывать это не нужно.
Чтобы определять размеры изображений асинхронно (например, загружая их), передайте
асинхронный `imageSizer` в `renderSvgAsync`; см. [Изображения](/ru/guide/images).

## Web Workers

Компоновка выполняется синхронно, поэтому большой граф блокирует поток, в котором
запущен. Запускайте её в Worker, чтобы страница оставалась отзывчивой. Внутри Worker нет
`document`, поэтому библиотека измеряет текст с помощью `OffscreenCanvas`, а
асинхронный API загружает шрифты через собственный набор шрифтов Worker (`self.fonts`).

Шрифты в Worker отделены от шрифтов страницы: регистрируйте их в Worker через API
`FontFace` (правила CSS `@font-face` до Workers не доходят).

```ts
// graph-worker.ts (module worker)
import { renderSvgAsync } from '@knowvah/dot-engine';

self.fonts.add(new FontFace('Inter', 'url(/fonts/Inter.woff2)'));

self.onmessage = async (e: MessageEvent<string>) => {
  const { svg, fontIssues } = await renderSvgAsync(e.data, 'dot');
  self.postMessage({ svg, fontIssues });
};
```

Выполняйте рендеринг в Worker через `renderSvgAsync` (или `renderAsync`), а не
`renderSvg`, по крайней мере пока не загрузится каждый веб-шрифт. Chromium продолжает
измерять строку шрифта запасным начертанием, если именно эта строка была измерена в
Worker до загрузки начертания, — даже после его загрузки; асинхронный API загружает
шрифты до измерения, поэтому с этим никогда не сталкивается.

## Чего не стоит ожидать

Библиотека нацелена на **SVG** (а также текстовые форматы `json` / `xdot` / `dot` /
карта изображения). Растровый вывод (PNG/JPG), PostScript/PDF и интерактивные/GUI-бэкенды
вне рамок задачи — если нужен другой формат, конвертируйте SVG на следующем этапе.
Полные границы применимости см. в разделе [Известные расхождения](/ru/divergences).

## Большие графы: предварительный рендеринг в SVG

Очень большие графы — примерно **более 10 тыс. узлов или несколько МБ исходного кода
DOT** — непрактично компоновать во время выполнения в браузере. Компоновка
(mincross, ранжирование, трассировка сплайнов) сверхлинейна, так что это **потолок
масштаба, общий с оригинальным Graphviz, а не ограничение именно этого механизма**: на
таких входных данных нативный `dot`, сборки на WASM (`@hpcc-js/wasm-graphviz`) и этот
механизм одинаково упираются в тайм-аут или нехватку памяти. (Этот механизм **не**
утекает — его куча на один рендеринг не растёт; предел определяется строго размером
графа. Измеренное сравнение см. на [панели производительности](/perf).)

Для графов такого масштаба **отрисуйте один раз при сборке и отдавайте готовый `.svg`**,
вместо того чтобы компоновать в браузере при каждом просмотре — тот же шаблон вы
применяли бы даже с нативным `dot`, поскольку запускать его на каждый запрос слишком
медленно.

Адаптеры для сайтов, работающие на этапе сборки, в
[knowvah/dot-plugins](https://github.com/knowvah/dot-plugins) (опубликованы в NPM)
делают именно это:

- `@knowvah/vitepress-plugin-dot` — VitePress (markdown-it), на этапе сборки
- `@knowvah/eleventy-plugin-dot` — Eleventy (markdown-it), на этапе сборки
- `@knowvah/docusaurus-plugin-dot` — Docusaurus (MDX/remark), на этапе сборки
- `@knowvah/dot-markdown-it` — интеграция с markdown-it, не зависящая от фреймворка

Для динамических графов, задаваемых пользователем, где рендеринг на этапе сборки
невозможен, ограничивайте интерактивный рендеринг графами разумного размера и
кэшируйте полученный SVG.
