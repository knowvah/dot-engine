# Измерение текста

Для компоновки dot нужны ширина и высота каждой метки, чтобы задавать размеры узлов и
размещать рёбра. @knowvah/dot-engine измеряет текст через единую подключаемую точку
расширения — `TextMeasurer` — и автоматически выбирает, какой использовать; либо вы
можете задать собственный.

## Контракт

Есть две разные цели, и им нужны разные измерители:

| Цель | Измеритель | Детерминирован? | Кернинг / шейпинг |
|------|------------|-----------------|-------------------|
| **Воспроизводимая компоновка** (одинаковый результат везде) | встроенная метрическая модель | да | нет |
| **Компоновка с учётом шрифтов хоста** (совпадает с шрифтом отрисовки) | canvas платформы | нет (зависит от шрифта) | да |

Сам нативный Graphviz учитывает шрифты хоста — его вывод зависит от шрифтов,
установленных на машине, где он запущен. @knowvah/dot-engine позволяет выбирать:
по умолчанию детерминированность, учёт шрифтов хоста — по вашему выбору.

## Автоматический выбор

Если вы не задаёте измеритель, @knowvah/dot-engine выбирает его на каждый рендеринг:

1. явно заданный через `setTextMeasurer` измеритель (имеет приоритет, если есть);
2. **браузер** (доступен `document`) → `<canvas>` страницы — с учётом шрифтов хоста,
   измеряет тем же шрифтом, которым браузер будет рисовать текст SVG;
3. **Node** → встроенная детерминированная метрическая модель.

У библиотеки **нулевые зависимости времени выполнения**, и она сама никогда не
импортирует ни библиотеку шрифтов, ни `canvas`, поэтому браузерный бандл остаётся
небольшим, а значение по умолчанию для Node никогда не читает файловую систему.

## Измерение с учётом шрифтов хоста в Node

Чтобы в Node получать вывод с рамками, подходящими под конкретный шрифт (настоящий
кернинг и шейпинг), установите необязательную peer-зависимость `canvas` и один раз
подключите её при запуске:

```ts
import { setTextMeasurer, CanvasTextMeasurer, renderSvg } from '@knowvah/dot-engine';
import { createCanvas } from 'canvas'; // optional peer dependency: `npm i canvas`

setTextMeasurer(new CanvasTextMeasurer(createCanvas(0, 0).getContext('2d')));

const svg = renderSvg('digraph { A -> B }', 'dot');
```

`canvas` объявлен как **необязательная peer-зависимость** — он не устанавливается, пока
вы сами не попросите. Когда Node в интерактивном терминале переходит на встроенную
модель, @knowvah/dot-engine один раз выводит эту подсказку; отключить её можно с помощью
`GV_FONT_QUIET=1`.

## Собственные измерители

`setTextMeasurer` принимает всё, что реализует `TextMeasurer`:

```ts
import { setTextMeasurer, type TextMeasurer } from '@knowvah/dot-engine';

const myMeasurer: TextMeasurer = {
  measure: (text, fontname, fontsize) => ({ w: text.length * fontsize * 0.6, h: fontsize }),
};
setTextMeasurer(myMeasurer);
setTextMeasurer(undefined); // restore automatic resolution
```

Встроенные реализации экспортируются для повторного использования: `CanvasTextMeasurer`
(оборачивает любой 2D-контекст), `EstimateTextMeasurer` (детерминированный эталон без
хинтинга, который совпадает с `estimate_textspan_size` Graphviz без графической среды —
**это значение по умолчанию для Node**) и `LutTextMeasurer` (таблица поиска с хинтингом
для каждого семейства шрифтов, доступная как необязательный вариант для более точных
размеров без нативной зависимости от `canvas`).

## Почему такое разделение

Кернинг, лигатуры и ширины не-ASCII-глифов зависят от таблиц шейпинга реального
шрифта — таблица ширин по символам не может их представить, а правильные значения
различаются от шрифта к шрифту (в моноширинном шрифте `<=` занимает две ячейки; в
пропорциональном `VA` сближаются кернингом). Поэтому воспроизводимая компоновка
использует фиксированную метрическую модель; чтобы совпасть с реальным шрифтом
отрисовки, нужно измерять именно этим шрифтом — это и делает измеритель на основе
canvas.
