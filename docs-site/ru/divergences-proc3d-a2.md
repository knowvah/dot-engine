# proc3d — каноническое расхождение A2 в метриках шрифта (историческое) {#proc3d-—-the-canonical-a2-font-metric-divergence-historical}

::: tip Статус: устранено — proc3d теперь соответствует
Начиная с перехода на `EstimateTextMeasurer` (`239c51b`, 2026-06-25), и порт, и
headless-оракул на C измеряют текст одной и той же моделью
`estimate_textspan_size`.
Повторный запуск приведённого ниже воспроизведения на текущем дереве исходников даёт
**0 различий, maxDelta 0** для `tests/graphs/proc3d.gv` — документированное на этой
странице отклонение больше не воспроизводится. Класс A2 в целом для экземпляров proc3d из
корпуса **схлопнулся**; актуальные, не замороженные счётчики см. в разделе [Известные расхождения §A2](/ru/divergences#a2-text-measurement-font-metrics-label-driven-layout)
и на странице [Паритет](/parity). Эта страница сохранена как исторический разбор
первопричины — описанный ниже механизм реален и поучителен, он просто больше не даёт
наблюдаемого отклонения на этом графе.
:::

`proc3d` (`graphs-proc3d` / `share-proc3d` / `windows-proc3d`) был хрестоматийным случаем
[A2 — метрик шрифта](/ru/divergences#a2-text-measurement-font-metrics-label-driven-layout):
субпиксельная разница в измерении текста сдвигала x-координаты узлов на несколько
пунктов, и граф оказывался в категории **structural-match**. Эта страница — отдельный
разбор, на который ссылается список расхождений; она описывает, *почему* так происходило,
до унификации измерителей текста.

## Почему возникало расхождение (первопричина, на тот момент) {#why-it-diverged-root-cause-at-the-time}

Компоновка по x сетевым симплекс-методом была точной; единственное отличие состояло в том,
что измеритель шрифта порта того времени возвращал для некоторых **широких меток**
ширину на долю пункта больше, чем измерение нативного оракула на основе FreeType. Самые
широкие метки proc3d — овалы с путями к файлам, например `/home/ek/work/src/lefty/lefty.c`,
та самая строка, которую [`known-divergences.md` §A2](/ru/divergences#a2-text-measurement-font-metrics-label-driven-layout)
измерил как **+0.75 pt (+0.43%)**. Более широкая метка давала чуть более широкий узел,
половина ширины которого входила в ограничения горизонтального разделения слева направо,
округлённые через `ROUND()`; затем сетевой симплекс-метод выбирал немного иное (столь же
оптимальное) целочисленное распределение x. Результатом стал почти равномерный сдвиг по x
**не более 3.55 pt** на рисунке шириной около 2620 pt — ранги, порядок, топология и
y-координаты остались идентичными. Исправлением стала не заплатка под proc3d: переход
на `EstimateTextMeasurer` поставил обе стороны на одну и ту же headless-модель измерения,
что устранило завышение измерений широких меток, вызывавшее этот сдвиг.

## Дельта — golden и наш результат, наложенные друг на друга {#the-delta-—-golden-vs-ours-overlaid}

Golden (**зелёный**) и наш результат (**красный**) наложены в одном кадре. В полном
масштабе они сливаются в коричневый — сдвиг незаметен глазу (отсюда
*structural-match*).

![Наложение proc3d: golden и наш результат, весь рисунок: зелёный — C, красный — @knowvah/dot-engine](/img/proc3d-overlay.svg)

При увеличении зелёно-красная кайма проявляется **почти исключительно на длинных овальных
метках с путями к файлам** — именно на тех широких строках, которые измеритель
завышает. Узлы с кодом и прямоугольники остаются совпадающими:

## Воспроизведение {#reproduce}

Нативный оракул запускается под headless-`GVBINDIR` (`/tmp/ghl`, из
`test/corpus/gen-headless-gvbindir.sh`), чтобы обе стороны использовали один и тот же
измеритель `estimate_textspan_size` — см.
[§A2 «Isolating the algorithm from the font backend»](/ru/divergences#a2-text-measurement-font-metrics-label-driven-layout).

```sh
# port
GV_TEXT_MEASURER=estimate \
  npx tsx test/corpus/render-one.ts ~/git/graphviz/tests/graphs/proc3d.gv dot

# native C oracle (headless, estimate measurer)
GVBINDIR=/tmp/ghl \
  ~/git/graphviz/build/cmd/dot/dot -Tsvg ~/git/graphviz/tests/graphs/proc3d.gv
```

Запуск этого сегодня даёт совпадающие SVG (0 различий при допуске `deterministic`
±0.01), а не описанную выше дельту в 3.55pt.
